# Лабораторная работа №7: ответы на вопросы (Задание 2)

1. **Что делают приложения?**
   - TCP: `tcpserver` ждёт соединения, принимает байты клиента и печатает их в stdout
     (клиентов обслуживает по одному, ответа не отправляет). `tcpclient` читает stdin
     и отправляет прочитанное серверу.
   - UDP: `udpserver` это эхо-сервер: получает датаграмму, печатает её и адрес
     отправителя, возвращает те же байты. `udpclient` отправляет строку и печатает ответ.
2. **tcpclient -> незапущенный сервер.** `connect: Connection refused`, клиент сразу
   завершается с кодом 1: ОС сервера отвечает пакетом RST, порт никто не слушает.
3. **udpclient -> незапущенный сервер.** Ошибки нет: `sendto` успешен (он значит лишь
   "пакет отправлен"), затем `recvfrom` ждёт ответа бесконечно, клиент зависает.
4. **tcpclient отвалился.** Закрытие/убийство процесса: ядро отправляет FIN, `read`
   на сервере возвращает 0, сервер закрывает сокет и ждёт следующего клиента.
   Аварийный обрыв (RST): `read` возвращает -1 (ECONNRESET), и `tcpserver` завершается
   (`exit(1)` в коде). Полное исчезновение хоста без FIN/RST: сервер не узнает
   об этом, пока не сработают keepalive/таймауты, и остаётся заблокирован в `read`.
5. **udpclient отвалился.** Ничего: у UDP нет соединения, сервер ничего не знает о
   клиенте, ответ уходит "в никуда", сервер продолжает работать.
6. **udpclient -> несуществующий/выключенный сервер.** Как в п.3: `sendto` успешен,
   `recvfrom` зависает навсегда. (Ошибка возможна только если сеть сразу сообщает, что
   маршрута нет: `sendto` вернёт ENETUNREACH.)
7. **tcpclient -> несуществующий/выключенный сервер.** `connect` блокируется:
   SYN остаётся без ответа и повторяется; в Linux по умолчанию около 127 секунд
   (`tcp_syn_retries=6`), затем `Connection timed out`. Если маршрутизатор ответит
   ICMP "unreachable", ошибка (`No route to host`) придёт сразу.
8. **Отличия UDP и TCP:**

   | | TCP | UDP |
   |---|---|---|
   | Соединение | да (рукопожатие, `connect`/`accept`) | нет |
   | Доставка | гарантирована, подтверждения, повторные передачи | не гарантирована, пакеты могут теряться |
   | Порядок | сохраняется | не гарантируется |
   | Границы сообщений | нет, это поток байт | есть, одна датаграмма = одно сообщение |
   | Дубликаты | отбрасываются | возможны |
   | Контроль перегрузки/потока | есть | нет |
   | Накладные расходы | выше | ниже |
   | Применение | веб, почта, передача файлов | DNS, видео/голос, игры |
